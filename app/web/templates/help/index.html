🚀 Démarrage

▸ Créer son bot Discord
  1. Va sur le Discord Developer Portal → New Application → donne un nom.
  2. Onglet Bot → Reset Token → Copy pour récupérer le token (garde-le secret).
  3. Onglet OAuth2 → URL Generator : coche les scopes bot et applications.commands.
  4. Dans Bot Permissions : Send Messages, Embed Links, Manage Messages, Read Message History, Create Public Threads, Send Messages in Threads, Manage Threads.
  5. Copie l'URL générée en bas, ouvre-la, choisis ton serveur → Autoriser.

💡 Aucun intent privilégié n'est nécessaire — laisse-les désactivés.

▸ Récupérer les IDs (serveur & channels)

Active le mode développeur dans Discord : Paramètres → Avancés → Mode développeur.

  • ID du serveur : clic droit sur l'icône du serveur → Copier l'identifiant.
  • Channel par défaut : clic droit sur le salon des notifications → Copier l'identifiant.
  • Channel de monitoring : idem sur le salon dédié au suivi.

Les IDs sont de longs nombres, ex. 123456789012345678.

▸ Connecter Home Assistant

Dans HA : profil → Sécurité → Jetons d'accès longue durée → Créer, puis copie le jeton.

Pour déclencher une notif depuis HA, ajoute ce rest_command :

rest_command:
  bot_discord:
    url: "http://IP_BOTPANEL:8080/api/notify"
    method: POST
    content_type: "application/json"
    payload: '{"id": "{{ id }}"}'

Puis dans une automatisation : service: rest_command.bot_discord avec id: "mon_slug".

▸ Assistant de configuration (1er lancement)

Au premier démarrage, si rien n'est configuré, ouvre http://IP:8080 : un formulaire te demande le token Discord, les IDs et les infos Home Assistant. Tu remplis, tu enregistres, le service redémarre seul. Aucune manipulation en console.

🔔 Utilisation

▸ Créer une notification

Slug

Identifiant unique (minuscules, chiffres, underscore) : c'est lui qu'on appelle pour déclencher la notif.

Mode d'envoi

  • Direct : message dans le channel choisi.
  • Thread : message dans un fil du channel texte (regroupé par le nom du fil).
  • Forum : message dans un post d'un channel forum Discord.

Groupe (rangement sur le site)

Champ indépendant de Discord : sert juste à ranger les notifications dans la liste du site.

Embed

Titre, message (Markdown : **gras**, *italique*…), couleur, icône, footer, timestamp, boutons (Supprimer / Snooze / action HA) et champs.

▸ Placeholders — afficher des valeurs Home Assistant

Dans le message ou un champ, insère des états HA :

  • {state:sensor.temp} — état brut
  • {state:sensor.temp|--} — avec valeur de secours si HA est indisponible
  • {attr:sensor.temp:friendly_name} — un attribut précis
  • {unit:sensor.temp} — l'unité (ex. °C)

▸ Commandes slash

Des commandes / personnalisées, gérées depuis le site et synchronisées avec Discord.

  • Action : service HA, script, scène, ou envoi d'une notification.
  • Message de réponse (éphémère) après exécution.
  • Activable / désactivable. Les noms ha et clear sont réservés.
▸ Monitoring

Des messages épinglés qui se mettent à jour tout seuls à intervalle régulier (température, conso…).

  • Chaque bloc affiche des champs (entité HA + icône + suffixe).
  • Intervalle minimum : 30 secondes.
  • Si le message est supprimé sur Discord, il est recréé automatiquement.

🔌 Envoyer une notif depuis un projet (API)

L'idée en une phrase : tu crées la notification ici (avec un slug), et n'importe quel projet peut la déclencher en envoyant ce slug par une simple requête.

1
Crée la notif
dans Notifications, note son slug (ex. backup_done).
2
Ton projet l'appelle
une requête HTTP avec le slug.
3
Ça part sur Discord ✨
BotPanel gère toute la mise en forme.

La requête

POST http://IP_BOTPANEL:8080/api/notify
Content-Type: application/json

{ "id": "backup_done" }

Avec du texte qui change (variables)

Mets des trous {var:nom} dans le texte de la notif…

Titre :   ✅ Backup VM {var:vmid} terminé
Message : Durée : {var:duree} · Taille : {var:taille|inconnue}

…puis envoie les valeurs dans vars :

{ "id": "backup_done",
  "vars": { "vmid": "100", "duree": "2m34s", "taille": "2.1 Go" } }

→ ✅ Backup VM 100 terminé — Durée : 2m34s · Taille : 2.1 Go

  • {var:nom} → la valeur envoyée (vide si oubliée)
  • {var:nom|défaut} → la valeur, ou défaut si oubliée

🔓 Cette route reste toujours accessible, même avec la protection par mot de passe : tes projets ne sont jamais bloqués.

⚙️ Administration

▸ Paramètres, mise à jour & redémarrage
  • Presets de couleurs et de channels, réutilisables partout.
  • Mise à jour : récupère la dernière version depuis GitHub, depuis l'UI.
  • Redémarrage : relance le service (l'interface revient après quelques secondes).
  • Threads actifs : liste des fils créés ; supprimer une entrée force la recréation.
▸ Sauvegarde & migration

Dans Paramètres → Sauvegarde & migration :

  • Exporter : télécharge un fichier JSON de toutes tes données (notifs, commandes, monitoring, presets).
  • Importer : recharge ce fichier sur une nouvelle instance. ⚠️ Remplace les données existantes.
▸ Compte & sécurité (login)

La protection par mot de passe est optionnelle (compte unique admin).

  • Activer / changer / désactiver : Paramètres → Compte & sécurité.
  • Mot de passe oublié : sur le serveur, bash deploy/reset_admin.sh puis redémarre.
  • Les routes machine (/api/notify) restent toujours ouvertes.

Détails : fichier docs/CONNEXION.md du projet.
