1. Créer son bot Discord (pas à pas)

Compte à prévoir : environ 5 minutes. Aucune ligne de code.

Étape 1 — Créer l'application

  1. Va sur le Discord Developer Portal et connecte-toi.
  2. Clique sur New Application (en haut à droite).
  3. Donne un nom (ex. BotPanel) → Create.

Étape 2 — Activer le bot & copier le token

  1. Dans le menu de gauche, ouvre l'onglet Bot.
  2. Clique sur Reset Token (ou Add Bot selon la version) → confirme.
  3. Clique sur Copy pour copier le token. ⚠️ Garde-le secret, ne le partage jamais.

💡 Bonne nouvelle : BotPanel n'a pas besoin d'intents privilégiés. Tu peux laisser Message Content Intent, Server Members et Presence désactivés.

Étape 3 — Générer le lien d'invitation

  1. Ouvre l'onglet OAuth2 → URL Generator.
  2. Dans Scopes, coche : bot et applications.commands.
  3. Dans Bot Permissions, coche au minimum :
    • Send Messages
    • Embed Links
    • Manage Messages (pour le bouton Supprimer)
    • Read Message History
    • Create Public Threads & Send Messages in Threads (pour les modes Thread / Forum)
    • Manage Threads
  4. Copie l'URL générée tout en bas.

2. Inviter le bot & récupérer les IDs

Inviter le bot

  1. Colle l'URL générée dans ton navigateur.
  2. Choisis ton serveur Discord → Autoriser.
  3. Le bot apparaît (hors-ligne pour l'instant, c'est normal tant que BotPanel n'est pas lancé).

Activer le mode développeur

Dans Discord : Paramètres utilisateur → Avancés → Mode développeur (active-le). Ça débloque le « Copier l'identifiant ».

Récupérer les IDs à saisir dans BotPanel

  • ID du serveur : clic droit sur l'icône de ton serveur → Copier l'identifiant du serveur.
  • Channel par défaut : clic droit sur le salon texte où arriveront les notifications → Copier l'identifiant du salon.
  • Channel de monitoring : pareil, sur le salon dédié aux messages de suivi (température, conso…).

Ces IDs sont de longs nombres (ex. 123456789012345678).

3. Connecter Home Assistant

Créer un token longue durée

  1. Dans Home Assistant : clique sur ton profil (en bas à gauche).
  2. Onglet Sécurité → section Jetons d'accès longue durée → Créer un jeton.
  3. Donne un nom, puis copie le jeton (il ne sera affiché qu'une fois).

🔒 Conseil : ce jeton donne accès à ton HA. Ne le partage pas.

Déclencher une notification depuis HA

Une fois BotPanel configuré, HA n'a qu'un seul appel à faire. Ajoute ce rest_command dans ta config HA :

rest_command:
  bot_discord:
    url: "http://IP_DE_BOTPANEL:8080/api/notify"
    method: POST
    content_type: "application/json"
    payload: '{"id": "{{ id }}"}'

Puis, dans une automatisation, appelle :

action:
  - service: rest_command.bot_discord
    data:
      id: "slug_de_ta_notification"

4. Assistant de configuration (1er lancement)

Au tout premier démarrage, si BotPanel n'est pas encore configuré, ouvre http://IP:8080 : un assistant te demande le token Discord, les IDs et les infos Home Assistant. Tu remplis, tu cliques Enregistrer et démarrer — tout est sauvegardé et le service redémarre seul. Aucune manipulation de fichier n'est nécessaire.

5. Notifications

Slug

Identifiant unique appelé depuis Home Assistant (rest_command.bot_discord avec id: <slug>). Minuscules, chiffres et underscore uniquement.

Mode d'envoi & nom du fil / post

  • Direct : le message part dans le channel choisi.
  • Thread : le message va dans un fil du channel texte (le nom du fil regroupe les messages). Le fil est créé/réutilisé automatiquement.
  • Forum : le message est posté dans un channel forum Discord (tu choisis un post existant ou tu en crées un nouveau).

Groupe (rangement sur le site)

Champ indépendant de Discord : il sert uniquement à organiser la liste des notifications sur ce site (les notifications d'un même groupe sont regroupées dans un bloc repliable).

Couleur

Clique sur la pastille pour une couleur personnalisée, ou choisis un preset enregistré dans Paramètres → Couleurs.

Markdown dans le message

Discord supporte le markdown : **gras**, *italique*, __souligné__, ~~barré~~, `code`. Sélectionne du texte et utilise les boutons B / I de la barre d'outils.

Boutons

Supprimer et Snooze sont gérés par le bot. Les boutons d'action appellent un service Home Assistant au clic (ex. light.turn_on sur light.salon).

Champs (fields)

Affichés en grille dans l'embed Discord. Leur valeur peut contenir des placeholders (voir section suivante).

Mention

Ajoute une mention (@everyone, @here, un rôle ou un utilisateur) envoyée avec la notification pour qu'elle notifie vraiment.

Timestamp

Quand activé, la date d'envoi est ajoutée au pied de l'embed (ex. 28 avril 2026 à 14:05).

6. Placeholders & templates

Dans le message ou la valeur d'un champ, deux syntaxes sont supportées (mélangeables).

Syntaxe BotPanel (rapide)

  • {state:sensor.temp} — état brut
  • {state:sensor.temp|--} — avec valeur de secours si HA est indisponible
  • {attr:sensor.temp:friendly_name} — un attribut précis
  • {unit:sensor.temp} — l'unité (ex. °C)

Syntaxe Jinja Home Assistant (puissante)

{% raw %}
  • {{ states('sensor.temp') }}
  • {{ state_attr('sensor.x', 'attr') }}
  • {% if states('binary_sensor.porte') == 'on' %}ouverte{% else %}fermée{% endif %}
{% endraw %}

Exemple : {state:sensor.temp_salon} {unit:sensor.temp_salon} affichera 21.5 °C.

7. Commandes slash

Des commandes / personnalisées, gérées depuis le site et synchronisées avec Discord à chaque modification.

  • Chaque commande a une action : appeler un service HA, lancer un script, activer une scène, ou envoyer une notification.
  • Un message de réponse (éphémère) confirme l'exécution.
  • Les commandes sont poussées sur ton serveur (propagation immédiate). Les noms ha et clear sont réservés.
  • Une commande peut être désactivée sans la supprimer.

8. Monitoring

Des messages Discord épinglés et mis à jour automatiquement à intervalle régulier (température, consommation, état des machines…).

  • Chaque bloc affiche une série de champs (entité HA + icône + suffixe).
  • Intervalle de rafraîchissement configurable (minimum 30 secondes).
  • Si le message épinglé est supprimé côté Discord, il est recréé automatiquement au cycle suivant.

9. Paramètres, mise à jour & sauvegarde

  • Presets de couleurs / channels : réutilisables dans tous les formulaires.
  • Mise à jour : récupère la dernière version depuis GitHub (git), directement depuis l'UI.
  • Redémarrage : relance le service depuis l'UI (l'interface revient après quelques secondes).
  • Threads Discord actifs : liste des fils créés ; supprimer une entrée force la recréation au prochain envoi.
  • Sauvegarde & migration : Exporte toutes tes données (notifications, commandes, monitoring, paramètres) dans un fichier JSON, puis Importe-le sur une nouvelle instance. ⚠️ L'import remplace les données de configuration existantes.

10. Déclencher une notification depuis un projet (API)

N'importe quel projet (script, serveur, app…) peut déclencher une notification Discord via une simple requête HTTP. Tu crées la notification une fois ici (avec un slug), et ton projet envoie ce slug.

La requête

POST http://IP_BOTPANEL:8080/api/notify
Content-Type: application/json

{ "id": "mon_slug" }

Cette route reste toujours accessible, même avec la protection par mot de passe activée : tes intégrations ne sont jamais bloquées.

Texte dynamique — variables {var:...}

Pour insérer des valeurs dynamiques (nombres, noms, durées…), écris des trous {var:nom} dans le titre, le message ou un champ de la notification :

  • Titre : ✅ Backup VM {var:vmid} terminé
  • Message : Durée : {var:duree} · Taille : {var:taille|inconnue}

Puis ton projet envoie les valeurs dans vars :

POST http://IP_BOTPANEL:8080/api/notify
{
  "id": "backup_done",
  "vars": { "vmid": "100", "duree": "2m34s", "taille": "2.1 Go" }
}

→ Résultat : ✅ Backup VM 100 terminé — Durée : 2m34s · Taille : 2.1 Go

  • {var:nom} — remplacé par la valeur ; vide si non fournie
  • {var:nom|défaut} — remplacé par la valeur, ou défaut si non fournie

📄 Guide complet à envoyer à un développeur (exemples Python, Node.js, PHP, Bash, Home Assistant) : voir le fichier docs/API.md du projet.
